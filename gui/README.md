# AeroLab desktop GUI

English policy evaluation interface for the existing Tello/M30 project. Run from a Linux graphical desktop:

```bash
python gui/app.py
```

The optional desktop interface requires PyQt5. Install `PyQt5>=5.15` in your Python environment before running `python gui/app.py`. The browser interface does not require Qt.

- Select an aircraft and an existing MARL checkpoint (one most recent checkpoint per experiment).
- Model information comes from the checkpoint, including saved training settings, weight shapes (hover over model information), actor/critic parameter counts and completed training steps. Parameters remain read-only.
- Tello starts with the `fixed_w3_ind` experiment, at its trained 1 m/s speed. M30 starts with `m30_xy5_z1_w10_finetune` at its trained horizontal speed of 5 m/s. Runtime speed overrides do not change the saved model.
- Mean wind greater than 15 m/s blocks Run. Existing aircraft preflight checks remain in force: Tello uses its 3.5 m/s measured-wind threshold; M30 uses 15 m/s. Measured gusty wind may differ from the requested mean.
- Command delay can be enabled/disabled and is quantized to the environment's 100 ms control step. Other existing sensor noise and domain randomization remain active.
- Fast simulation executes real checkpoint inference and plots the resulting positions. It supports both aircraft. Gazebo mode renders actual Gazebo camera frames for Tello; the project has no M30 Gazebo model, so that option is disabled for M30.
- The idle viewport shows a clearly labelled recorded project capture. The Run button begins an evaluation from the trained task's airborne initial positions; it does not command a physical takeoff. Stop cancels at the next simulation frame and closes resources. No physical drone is connected.
- Controls are locked while running. There is no manual landing command: the trained policy controls the landing task.

Headless preview:

```bash
QT_QPA_PLATFORM=offscreen python gui/app.py --screenshot docs/gui_preview.png
QT_QPA_PLATFORM=offscreen python gui/app.py --smoke-run --screenshot docs/gui_running.png
```

If Qt reports `could not connect to display`, the terminal has no accessible graphical display. A server terminal without a desktop cannot show the interactive Qt window. Use a remote graphical desktop or SSH X11 forwarding for interactive desktop mode. Setting `DISPLAY=:0` alone does not create a display service. For screenshots, `--screenshot` now selects offscreen rendering automatically when no display variables are present.

## Browser GUI (recommended on the remote server)

The server now hosts an English browser console with AI Policy and Manual Flight modes. No X11 display is required.

- **Local backend:** `http://127.0.0.1:18080`.
- **Remote access:** forward local port 18080 to the server through your SSH connection, then open `http://localhost:18080`.
- To run manually from the repository root: `python gui/web_server.py --port 18080`.

Manual Flight supports world-axis velocity commands: W/S = +/-Y, A/D = -/+X, Up/Down = +/-Z. Hold the key or the on-screen button. Space/Hold requests zero velocity. Select North/East/South/West to control one aircraft; others receive zero velocity commands. The velocity controller can drift under wind; this is not a guaranteed position lock. Yaw is not implemented. The project starts from airborne initial states, so Start flight starts a simulation episode rather than executing a ground takeoff.

Commands expire after 400 ms without browser updates, then zero commands enter the configured delay queue. Releasing a key, switching aircraft, losing window focus or hiding the tab clears the browser's pressed keys. Configured delay and physical inertia mean motion can continue after release. Horizontal diagonal input is normalized to prevent exceeding the command speed limit. Stop ends the episode and closes its resources; Reset clears the stopped scene. Stop may wait for an in-progress Gazebo operation to return.

The server runs one episode shared by the authenticated instance user. Settings are locked during a running episode. Both aircraft support Fast simulation; only Tello has a Gazebo model. Mean wind >15 m/s is rejected in both browser and server, and existing aircraft measured-wind preflight checks are retained.

Source: `gui/web_server.py` and `gui/web/{index.html,style.css,app.js}`. The original Qt interface remains available separately.

### Detailed Tello model and close-up camera

Tello now uses original, smooth OBJ visuals generated by `tools/build_tello_visuals.py`: shell, motor/arm assemblies, guard rings, sculpted propellers, camera/lens and small hardware details. This is a Tello-inspired illustrative model rather than official DJI CAD. The original collider, mass, inertia and controller/motor parameters are preserved. M30 still uses the fast environment.

On a fresh page Tello defaults to Gazebo and Aircraft close-up. Change **Camera view** to Fleet overview to see the full landing station, or select **Camera target** to inspect another aircraft. Camera changes are available during both manual and AI episodes. Refresh the browser after updating the server. Latest screenshots are also copied to the current Codex workspace's `fig` directory.
